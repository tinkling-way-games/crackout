# autopilot: 自走開発の手順

## 0. タスクを決める

- 引数でタスク (Issue 番号・説明) が渡されたらそれをやる。
- なければ `docs/TASKS.md` の `## Ready` から先頭の1件を取る。`Ready` が空なら、何もせずその旨を報告して終わる。
- 取ったタスクは `## Doing` に移す。

## 1. 受け入れ条件を固める

- タスクから「何ができたら完了か」をチェックリストに書き出す。
- 書けない場合 (目的が不明、仕様が矛盾) は実装に入らず、疑問点を列挙して人間に返す。

## 2. 調査と計画

- 関係するコードを読む。広く探す必要があるときは Explore サブエージェントに任せ、結論だけ受け取る。
- 変更するファイルと手順を箇条書きで計画する。

## 3. 実装ループ

以下を受け入れ条件がすべて満たされるまで繰り返す:

1. 失敗するテストを書く (または既存テストで再現する)
2. 最小の実装で通す
3. `scripts/verify.sh` を実行
4. 通ったらコミット (`feat:` / `fix:` / `refactor:` / `test:` / `docs:` プレフィックス)

同じ失敗で3回つまずいたら、アプローチを変えるか、状況をまとめて人間に聞く。

## 4. セルフレビュー

- `reviewer` サブエージェントに差分 (`git diff main...HEAD`) をレビューさせる。
- 指摘のうち正しいものは直し、直さないものは理由を記録する。

## 5. 記録と引き渡し

- `docs/PROGRESS.md` に日付付きで追記する: やったこと / 判断とその理由 / 残課題。
- `docs/TASKS.md` でタスクを `## Done` に移す。
- ブランチを push し、PR 作成を依頼されていれば PR を作る (本文に受け入れ条件のチェックリストと検証結果を載せる)。
